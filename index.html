1. Can Welo see my other browser tabs?

Yes. It can collect the URLs of open tabs when an activity event is sent. It does not, in the inspected RaterHub path, read the page contents of unrelated tabs.

It also counts new tabs opened while an activity event is active.

2. Can it record my whole screen?

No automatic whole-screen recording was found in the active RaterHub flow. Sentry Replay reconstructs the webpage and can include page interactions; it does not automatically record your monitor or unrelated tabs.

Production session replay remains sampled at 10%. Since 3.4.0, additional error-triggered replay sampling is 0%, performance trace sampling is 0%, and media is blocked. Visible page text has no global mask; form inputs are masked. Request and response body capture is disabled for Replay.

3. Does it track my mouse or keyboard?

No general mouse-movement, cursor-coordinate, scrolling-speed or keystroke tracker was found. RaterHub copy/paste prevention is disabled.

There is one narrow mouse listener for the Cancel and Release controls. It sends an internal event; it does not click the control automatically.

Sentry Replay may include page interactions in a selected replay. No separate general keystroke logger was found in the reviewed RaterHub code; this does not mean a selected replay is free of interaction data.

4. Can it list my other installed extensions?

No direct list was found. The manifest does not request Chrome's management permission, which is normally required to obtain the names, IDs or versions of installed extensions.

The source contains a fallback collector for this information. In the installed package, the API is unavailable because the manifest has no management permission, so the collector returns empty values.

5. Can it identify an auto-submit or workflow helper?

Welo can see that RaterHub completed a task, but it does not identify which tool or extension caused the action.

It watches successful RaterHub completion requests such as /preview or /commit. The event does not contain an autoSubmit flag, another extension's ID, click coordinates or a general mouse trace.

6. What changed in version 3.4.0?

Sentry settings and identity context changed. Error-triggered replay sampling fell from 100% to 0%, performance trace sampling from 100% to 0%, and media blocking was enabled. Normal production replay sampling stayed at 10%.

Sentry gained explicit platform, action, task and platform-user context. The user identifier can be your RaterHub email. The replay should not be described as anonymous: earlier versions already had session identifiers and potentially identifying visible text.

7. Does it collect location or device information?

Yes. When you are logged in, the extension can contact ipwho.is to receive the ISP, country and region linked to your public IP.

This means ipwho.is can see the public IP used for that request. The check can run in the background after login, even before a task is submitted. The inspected RaterHub activity event does not include the IP lookup fields. This check is separate from Sentry and tab URLs.

The extension also creates a random device token and contains broader local fingerprint collection, including offscreen/browser signals. These capabilities are not new in 3.4.1. The inspected normal RaterHub activity payload excludes device-fingerprint and viewport fields; local collection and server transmission are different questions.

8. What does the new Check My Answer button do?

Click it to ask Welo to check your answer. It sends your answer and information about the task to Welo, then displays Welo’s reply. Depending on the page, the information sent can include your written comment and selected rating.

You cannot submit the task while the check is running. After the reply arrives, Submit may be unlocked or remain blocked, depending on the result. The button does not edit your answer or submit the task for you.

The code shows this behavior. It does not tell us why Welo introduced the button or whether using it affects your score.
