1. What does Check My Answer actually do?

It requests a review of your answer before you submit the task. In the normal UI flow, clicking the button reads the selected rating and task data, sends them to Welo, then displays the server’s findings. It does not rewrite the answer or automatically submit the task.

The button is enabled for recognized Factuality, Response Helpfulness and Side By Side layouts. It is not guaranteed to appear on every task. No periodic upload of the typed comment, or mandatory check on every native Submit, was found in these UI paths.

2. Why does it block Submit?

After local checks pass, the click handler blocks Submit while the request is pending. It then keeps the block when a triggered flag other than wrong_label has severity blocking, or when is_mvq and wrong_label are both triggered.

Proof: exact blocking conditions
function hasTriggeredFlag(data, name) {
	return Array.isArray(data?.flags)
		? data.flags.some((flag) => flag.name === name && flag.triggered)
		: false;
}

function hasMvqLabelMismatch(data) {
	return hasTriggeredFlag(data, 'is_mvq') && hasTriggeredFlag(data, 'wrong_label');
}

function hasOtherBlockingIssues(data) {
	return Array.isArray(data?.flags)
		? data.flags.some(
				(flag) =>
					flag.name !== 'wrong_label' &&
					flag.triggered &&
					flag.severity === 'blocking',
			)
		: false;
}

3.4.1 · content-script/raterhub-lint-check.js · lines 625–655 · Numbered evidence

Override and submit only unlocks in this callback. It does not call the native Submit action, and no separate override-recording POST was found here. An error response or caught exception unlocks; a request that never settles can leave the block in place.

The intended review-before-submission purpose is an inference from this behavior. The code does not establish penalties or changes to a rater’s score.

Technical limitations found
  • Unlocking enables the two controls without restoring their previous disabled state; confirmed with simulated buttons.
  • Editing the answer does not invalidate an outstanding result; an older result may affect the current answer.
  • Closing the results panel does not itself unlock Submit.
  • The new handler references an unimported showFlashMessage in error branches; an isolated test produced a ReferenceError, caught by the outer listener.
  • The background handler does not validate the supplied identity against the cache or require a RaterHub sender URL. A simulated call confirms this missing check; no live exploitation was performed. The normal click flow is not a security guarantee that every possible request requires a human click.

3. What happens without clicking Check My Answer?

A separate Factuality Assist lookup can run automatically. On a recognized task preview, after login and privacy-acceptance checks, it requests claim decomposition by task ID. This GET does not upload the comment or task body in its request body.

Proof: automatic lookup endpoint
async function displayClaimDecomposition(tabId, taskId) {
	if (!taskId) return;

	const response = await get(
		`/raterhub/llm-task-data/${encodeURIComponent(taskId)}/claim-decomposition`,
		{ silent: true },
	);
	const result = response?.data;
	if (result?.flow !== 'claim_decomposition' || !Array.isArray(result.subclaims)) {
		return;
	}

	await chrome.tabs.sendMessage(tabId, {
		action: 'showRaterhubClaimDecomposition',
		result,
	}).catch(() => {});
}

4. Does the update collect my email differently?

Yes: capture is more persistent. New navigation listeners schedule injections immediately and after 2, 5, 10 and 20 seconds, targeting all frames. The capture script polls once per second, observes DOM changes and has a 90-second timeout per instance. It caches the email as platformUserId_raterhub and sends an internal mail message when changed.

Proof: retries and navigation listeners
const RATERHUB_CAPTURE_DELAYS_MS = [0, 2000, 5000, 10000, 20000];

function injectRaterhubPlatformUserIdCapture(tabId) {
	chrome.scripting.executeScript({
		target: { tabId, allFrames: true },
		func: raterhubCapturePlatformUserIdScript,
	}).catch(() => {});
}

export function scheduleRaterhubPlatformUserIdCapture(tabId) {
	RATERHUB_CAPTURE_DELAYS_MS.forEach((delay) => {
		setTimeout(() => injectRaterhubPlatformUserIdCapture(tabId), delay);
	});
}

export function initRaterhubListeners() {
	const onRaterhubNavigation = (details) => {
		if (details.frameId !== 0) {
			return;
		}
		scheduleRaterhubPlatformUserIdCapture(details.tabId);
	};

	chrome.webNavigation.onCompleted.addListener(onRaterhubNavigation, {
		url: [{ hostSuffix: 'raterhub.com' }],
	});
	chrome.webNavigation.onHistoryStateUpdated.addListener(onRaterhubNavigation, {
		url: [{ hostSuffix: 'raterhub.com' }],
	});
}

6. Does it record my screen or typing?

The inspected active RaterHub flow does not record the whole monitor. Sentry Replay reconstructs the webpage and can include page interactions. Production session sampling is 10%, additional error-triggered sampling is 0%, visible text has no global masking, inputs are masked, and media is blocked. No additional general keystroke logger was found in the reviewed RaterHub code; that does not make replay interaction-free.

RaterHub copy/paste prevention remains disabled. A returned is_copy_paste lint flag is a server finding, not proof of a new clipboard listener or identification of another extension.

7. Can it identify my other extensions or auto-submit helper?

No explicit helper ID or auto-submit attribution was found in the inspected RaterHub event. It can observe task completion and changes to the page, which is different from proving which extension caused them.

The manifest still lacks management. The extension-inventory collector returns empty values when that API is unavailable. This conclusion is limited to the distributed client; it does not rule out server-side inferences.

8. What about location and device information?

The existing login-triggered warmup can contact ipwho.is for IP-related location/ISP data and cache a device token. The package also contains broader local fingerprint collection, including offscreen/browser signals; describing it only as an IP lookup would be incomplete.

Collection and transmission are separate questions: the unchanged normal activity-event path excludes fingerprint and viewport fields for RaterHub. This does not prove that every possible backend or telemetry path lacks identity data.
