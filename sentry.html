Correction to the old page: the 3.3.5 error-replay rate of 100% no longer describes this version. It became 0% in 3.4.0 and remains 0% in 3.4.1.

1. What is configured now?

Sentry provides diagnostic reporting and webpage replay. The production session replay rate is 10%, not a guarantee that exactly one in ten tasks is recorded. The non-production rate is 100%. A zero error-triggered replay rate does not prevent errors appearing within a session already selected for replay.

3.4.1 · plugins/sentry/content-script.js · lines 17–39 · Numbered evidence

Performance trace sampling is zero and default content-script integrations are disabled. Text visible on the page has no global mask. Form inputs are masked and media is blocked. Request/response bodies are disabled for Replay network capture.

2. Is the replay anonymous or gated by consent?

Do not describe it as anonymous. Since 3.4.0, shared context can explicitly associate platform, action, task and platform-user identity with Sentry. On RaterHub that identity can be an email. Even the earlier version had session tags and potentially identifying visible text.

3. What does this not prove?

No active RaterHub call enabling whole-screen recording or the library’s separate screenshot support was found. The optional image in the new Factuality request is extracted task content, not evidence of a screenshot of your monitor.

Masked input fields in Replay do not stop the separate Check My Answer POST from sending a comment. Static configuration also cannot establish whether your actual session was sampled, delivered, viewed or retained.

4. Did Sentry itself change in 3.4.1?

Yes. SDK 10.74.0 → 10.75.0; Welo’s own settings stayed identical. Five dependency source modules changed: version, collection-option resolution, missing LCP entries, an XHR error-reference cleanup and Replay attribute synchronization. In an isolated test, both resolvers returned the same collection options for the extension’s sendDefaultPii:false setting with no dataCollection override.

There is no evidence here of increased sampling or newly enabled network-body capture. “Same settings” does not mean the entire SDK implementation is unchanged. See the extracted version evidence.
